These provide identity/order/tree structure; parent alone cannot express all authorization/evidence dependencies. Parent IDs must resolve to earlier events within the same trace; root null is allowed only at sequence 1; sequence is contiguous. A later event must never be its own ancestor. Capture ordering is not evidence of elapsed runtime.

Manual fixtures deliberately identify authored UTC timestamps and null unmeasured latency. These are **draft-compatibility blockers**, not reasons to invent measurements. Draft `schema_version="1.0.0"` is a label in the draft, not evidence the contract was frozen.

## Mandatory correlation expectations

Request revision → state snapshot → model/tool proposal → argument validation → policy request → policy result → either suppression or dispatch → result → final claim. The authorized APPROVED-to-PO_CREATION transition must link the checked source state revision, resulting dispatch state revision and single dispatch claim to the same ALLOW/proposal. Approval evidence and supplier snapshot must be separately referenceable. Multiple failures do not overwrite earlier events. Retries have new invocation IDs but preserve proposal/request and idempotency relationships.

For PO recovery, record RECOVERY_PENDING, the trusted continuation, read-only ledger lookup outcome and original request/proposal/key/digest/dispatch/result references. A recovered result is an observation of the original creation, not a second tool execution. Preserve the original UNKNOWN_OUTCOME event; missing ledger evidence cannot prove non-execution. Canonical event names and continuation serialization remain Mohab's responsibility.

For RAG, preserve retrieval output separately from selected context. Reconstruct exactly what the model saw and which source supported each claim; neither a list of citation IDs nor a hash-only record suffices.

Evidence delivery failure must remain observable. Before mock purchasing dispatch, inability to retain/link mandatory authorization evidence must halt the action. Storage/acknowledgment mechanics and continuation identity are Mohab's design decisions; no guaranteed durability is claimed by this package.

## Pre-tool interface expectations, not a new API

The app requests a synchronous verdict against one immutable proposal/state snapshot. It expects ALLOW or BLOCK plus auditable policy findings/version and correlation to that proposal. Transport/schema are jointly defined in S1-02/S1-04. Incomplete results, mismatched versions, a changed snapshot, or technical error cannot authorize dispatch. The app does not retry a blocked action by quietly changing tool arguments.

Post-run interpretation consumes persisted original evidence and adds a separately versioned evaluation run. The app does not invoke the classifier/RCA to decide whether a risky action may execute. Re-evaluation never changes original approvals or tool outcomes. Human review does not overwrite machine decisions.
