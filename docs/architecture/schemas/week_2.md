### 2.2 Restricted `trustops-canonical-json-v1` Domain & Deterministic Cross-Language Test Vectors (`OD-13`)

Unlike general [RFC 8785 (JCS)](https://www.rfc-editor.org/rfc/rfc8785.html), which defines IEEE-754 double-precision float formatting and UTF-16 code-unit key sorting across arbitrary JSON values, **`trustops-canonical-json-v1`** enforces a restricted domain (`validate_canonical_json_domain(obj, allow_floats=False)`) on all digested tool arguments (`arguments_digest`) and business payloads (`business_payload_sha256`):

1. **Object Keys:** Non-empty ASCII identifier strings matching `^[A-Za-z0-9_.-]+$` (where UTF-8 code-point order and UTF-16 code-unit order are mathematically identical).

2. **Strings:** Unicode NFC-normalized strings (`unicodedata.normalize("NFC", s) == s`); monetary amounts are formatted as fixed 2-decimal strings (`"16000.00"`).

3. **Numbers:** Strict signed 64-bit integers (`-(2**63) <= n <= 2**63 - 1`); floating-point numbers (`float`), `NaN`, and `Infinity` are rejected in digested argument/business payloads with `ERR_CANONICAL_JSON_DOMAIN_VIOLATION` (`NEG-64`).

4. **Missing vs. `null` Semantics:** Omitted keys and explicit `null` values produce distinct canonical serializations and digests.

| Vector ID & Purpose | Input Object | Canonical UTF-8 Serialization (`trustops-canonical-json-v1`) | Verified SHA-256 Digest (`arguments_digest`) | 
| ----- | ----- | ----- | ----- | 
| **`VEC-01` (Key Ordering & Primitives)** | `{"z_key": 1, "a_key": "value", "m_key": True}` | `{"a_key":"value","m_key":true,"z_key":1}` | `sha256:6e5aaa32864f091389ecbc3adf91587a1677e1c280453416dd91b3c5b973b013` | 
| **`VEC-02` (Unicode NFC Preservation)** | `{"supplier_id": "SUP-088", "note": "Café — Crème", "quantity": 20}` | `{"note":"Café — Crème","quantity":20,"supplier_id":"SUP-088"}` | `sha256:1847323fd0c2840352ef5fa6da1bf7969a05572aa8fade6b7e16f57878095c96` | 
| **`VEC-03` (Explicit `null` vs. Omitted Key)** | `{"optional_field": None, "present_field": "ok"}` | `{"optional_field":null,"present_field":"ok"}` | `sha256:b279c37e774c002972060d73291c77e54ee751e7a1e78b6e2458515708933e17` |

### 8.2 Duplicate / Conflict, Redaction & Missing-Evidence Semantics (`Mohab.md` §6.3, §9 Week 2)

1. **Deterministic Pre-Storage Redaction:** Before computing `envelope_sha256` or committing to PostgreSQL, `redact_sensitive_fields()` replaces any key matching `{"api_key", "authorization", "x-goog-api-key", "password", "client_secret", "access_token"}` with `"[REDACTED_BY_TRUSTOPS_INGESTION_POLICY]"`.

2. **Idempotent Replay vs. Conflicting Replay:** Resubmitting an identical completed trace (`stored_hashes[trace_id] == envelope_sha256`) is a safe no-op returning HTTP `200 OK` (`IDEMPOTENT_REPLAY_ACCEPTED`). Submitting a modified payload under an existing `trace_id` returns HTTP `409 Conflict` (`ERR_CONFLICTING_TRACE_REPLAY`) and leaves existing database rows untouched.

3. **Unavailable Metadata & Missing Evidence Preservation:** Unavailable token counts or provider versions are stored as `null` with explicit `metadata_availability` reason codes (`UNAVAILABLE_PROVIDER_OMITTED`), never fabricated as `0`. Schema-valid traces that halt early or lack a committed tool result (Bucket A failure traces) are ingested normally so post-run evaluators can detect `UNSUPPORTED_COMPLETION`, `WORKFLOW_VIOLATION`, or `RETRIEVAL_FAILURE`.

### 10.2 Exact Selected-Passage Offset Mapping When Prompt Context Is Sliced

When a retrieved chunk's full normalized text $S =  ext{content\_snippet}$ is sliced before prompt insertion using 0-based Unicode code-point half-open interval $[a, b) =  ext{canonical\_chunk\_char\_span}$ (`0 <= a < b <= len(S)`):

1. **Selected Slice:** $C = S[a:b] =  ext{canonical\_chunk\_slice}$.

2. **Formatted Selected Block:** With prefix $P =  ext{formatting\_prefix\_applied}$ of length $L_P = \operatorname{len}(P)$, $E = P \mathbin{\Vert} C =  ext{exact\_selected\_text}$.

3. **Full-Chunk vs. Slice-Relative vs. Prompt-Block Offsets for Any Cited Quote** $Q =  ext{source\_quote}$**:**

   * **Full-Chunk Span (`source_char_span`):** $[q_{ ext{start}}, q_{ ext{end}})$ inside $S$, satisfying the mandatory containment invariant $a \le q_{ ext{start}} < q_{ ext{end}} \le b$ and $S[q_{ ext{start}} : q_{ ext{end}}] == Q$ (if $q_{ ext{start}} < a$ or $q_{ ext{end}} > b$, rejected with `ERR_CITATION_OUTSIDE_SELECTED_SLICE` in `NEG-21`).

   * **Slice-Relative Span (`slice_relative_char_span`):** $[s_{ ext{start}}, s_{ ext{end}}) = [q_{ ext{start}} - a,\; q_{ ext{end}} - a)$ inside `canonical_chunk_slice` ($C[s_{ ext{start}} : s_{ ext{end}}] == Q$, verified in `POS-30`).

   * **Formatted-Block Span:** $[L_P + q_{ ext{start}} - a,\; L_P + q_{ ext{end}} - a)$ inside `exact_selected_text` ($E$).

   * **Rendered-Prompt Context Block Span:** For the $k$-th selected chunk in `rendered_context_block` (`" "`-joined in `prompt_context_order`), where $B_k = \sum_{j < k} (\operatorname{len}(E_j) + 1)$, the quote lies at $[B_k + L_P + q_{ ext{start}} - a,\; B_k + L_P + q_{ ext{end}} - a)$.
